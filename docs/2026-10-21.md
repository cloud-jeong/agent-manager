# 2026-10-21 개발 기록: Agent 실행 환경 추가

## 요약
지금까지는 agent 정보(이름, system prompt, 공개 범위, 라벨)를 관리하는 UI와 REST API만 있었다. 오늘은 등록된 agent를 **실제로 실행하는 환경**을 추가했다.

- **채팅**: 브라우저에서 agent와 대화한다. 응답, 요약된 사고 과정, 도구 호출이 실시간으로 보인다.
- **도구 호출**
  - bash와 파일 편집: 대화마다 하나씩 띄우는 격리된 Docker 컨테이너에서 실행한다.
  - web search와 web fetch: Anthropic 서버에서 실행한다.
  - 원격 MCP 서버: admin이 등록한 서버를 agent가 골라서 쓴다.
- **비동기 실행 API**: 입력을 넣으면 백그라운드에서 실행되고, 결과는 나중에 조회한다.
- **Run 이력**: 모든 실행의 상태, 토큰 사용량, 소요 시간을 한 화면에서 본다.

설계 문서는 [runtime-plan.md](runtime-plan.md)에 있다. 데이터 구조는 [data-model.md](data-model.md), 흐름은 [sequence-diagrams.md](sequence-diagrams.md)의 11–14번을 보면 된다.

### 사용자 입장
- 상단 메뉴에 **Chat**과 **Runs**가 생겼다. admin에게는 **MCP Servers**도 보인다.
- agent 목록의 행 메뉴에 **Chat**이 생겼다.
- agent 편집 화면에 **Runtime** 섹션이 생겼다. 설정할 수 있는 항목은 다음과 같다.
  - 모델: Claude Opus 5.5(기본), Sonnet 5.5, Haiku 5.5, Fable 5.1
  - effort, 실행 1회당 최대 턴 수
  - 도구 켜기/끄기, 샌드박스 네트워크 허용, MCP 서버 선택
- 채팅 화면에서 할 수 있는 것
  - 응답이 생성되는 대로 보인다.
  - 도구 호출은 접을 수 있는 카드로 보인다(bash 명령과 출력, 파일 수정 diff).
  - Stop 버튼으로 실행을 멈출 수 있다.
  - 새로고침해도 진행 중인 응답에 다시 붙는다.
- 실행 권한: **볼 수 있는 agent는 실행할 수 있다.** 대화와 Run 기록은 만든 사람만 본다. admin도 다른 사람의 것은 볼 수 없다.

### 새 API
| Method | Path | 설명 |
|---|---|---|
| GET/POST | `/api/conversations` | 내 대화 목록 / 생성 |
| GET/PATCH/DELETE | `/api/conversations/{id}` | 대화 조회(메시지 포함) / 제목 변경 / 삭제 |
| POST | `/api/conversations/{id}/messages` | 메시지를 보내면 Run이 큐에 들어간다 |
| POST | `/api/agents/{id}/runs` | **비동기 실행**: `{"input": "..."}` → 202 |
| GET | `/api/runs`, `/api/runs/{id}` | Run 목록 / 상태와 결과(`output`) |
| GET | `/api/runs/{id}/events` | SSE 이벤트 스트림 (`Last-Event-ID`로 이어받기) |
| POST | `/api/runs/{id}/cancel` | 실행 취소 |
| GET/POST/PUT/DELETE | `/api/mcp-servers` | MCP 서버 관리 (변경은 admin만) |

예시:
```bash
curl -X POST http://localhost:8000/api/agents/<agent id>/runs \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"input": "Summarize the open issues"}'
curl http://localhost:8000/api/runs/<run id> -H "Authorization: Bearer <token>"
```

### 구조
- **모든 실행은 Run이다.** 채팅 메시지 하나도, API 호출 하나도 각각 Run 하나가 된다.
  - API 서버는 Run을 큐에 넣고 바로 응답한다.
  - 실행은 별도의 **worker 프로세스**(`python -m app.worker`)가 맡는다.
- **큐는 기존 Postgres를 쓴다.** `FOR UPDATE SKIP LOCKED`로 Run을 가져가고, `LISTEN/NOTIFY`로 서로를 깨운다. Redis 같은 새 인프라가 필요 없다.
- **진행 상황**은 `run_events` 테이블에 기록하고 SSE로 보낸다. 연결이 끊겨도 실행은 계속되고, 다시 연결하면 이어서 받는다.
- **대화 기록은 append-only다.** 모델 응답을 원본 그대로 저장하고 다음 요청에 그대로 보낸다. thinking block이 대화에 묶여 있어서 기록을 고치면 안 되기 때문이다.
- **장애 처리**
  - worker는 2초마다 heartbeat를 남긴다. 60초 넘게 끊기면 다른 worker가 그 Run을 `failed`로 처리한다.
  - 자동 재시도는 하지 않는다. 도구가 이미 부수효과를 냈을 수 있기 때문이다.

## 실행 방법 (변경된 부분)
```bash
cp .env.example .env          # ANTHROPIC_API_KEY 설정 필요
make up                       # 샌드박스 이미지 빌드 + postgres + backend + worker + frontend
```
로컬 개발 시에는 기존 명령에 두 가지가 추가된다.
- `make sandbox-image`: 샌드박스 이미지를 처음 한 번 빌드한다.
- `make dev-worker`: worker를 실행한다.

새 환경변수 (`.env.example` 참고):

| 변수 | 용도 |
|---|---|
| `ANTHROPIC_API_KEY` | worker가 Claude API를 호출할 때 쓴다 |
| `AGENT_MANAGER_SECRET_KEY` | MCP 서버 token 암호화 키. **바꾸면 기존 token을 복호화할 수 없다** |
| `AGENT_MANAGER_WORKER_CONCURRENCY` | worker 하나의 동시 실행 수 (기본 4) |
| `AGENT_MANAGER_SANDBOX_RUNTIME` | 컨테이너 런타임 (예: gVisor는 `runsc`) |

## 보안 관련 주의
- **worker는 Docker 소켓을 마운트한다.** 이는 호스트 root 권한과 같다.
  - 개발 환경에서는 문제없다.
  - **운영에 배포할 때는 gVisor(`AGENT_MANAGER_SANDBOX_RUNTIME=runsc`)를 쓰거나 샌드박스를 별도 호스트로 분리해야 한다.**
- 샌드박스 컨테이너의 격리 설정
  - 비 root 사용자, 모든 capability 제거, 읽기 전용 루트 파일시스템
  - 메모리·CPU·프로세스 수 제한, 명령당 timeout 120초
  - 네트워크는 기본으로 차단한다. agent 설정에서 켤 때만 연결한다.
- MCP 서버 token은 암호화해서 저장하고, API 응답에는 절대 넣지 않는다.

## 검증
- **백엔드 테스트 74개 통과** (`make test`)
  - 실행 경로는 가짜 LLM과 가짜 샌드박스로 검증한다.
    - 대상: 도구 루프, pause_turn, 턴 제한, 거절, 잘린 도구 호출, 취소, worker 종료, heartbeat 끊김, SSE 이어받기, 권한
  - SDK 요청 형식과 스트림 파싱은 가짜 HTTP 응답으로 검증한다.
  - 실제 Docker 컨테이너에서 확인한 것
    - 비 root 실행, 네트워크 차단, 읽기 전용 파일시스템
    - 작업 디렉토리 유지, 재시작 후 파일 보존
    - timeout, 대화 삭제 시 정리
- **frontend**: `pnpm lint`, `type-check`, `build` 통과
- **브라우저 확인**: 스크립트로 동작하는 가짜 모델로 확인했다.
  - 채팅 스트리밍, 도구 카드, markdown(표, 코드)
  - Stop, 실제 샌드박스에서 파일 생성·수정·실행
  - MCP 서버 등록, Run 이력
- **아직 확인하지 않은 것: 실제 Claude API 호출.** 작업 환경에 API 키가 없어서 확인하지 못했다. `ANTHROPIC_API_KEY`를 설정한 뒤 실제 대화로 한 번 확인해야 한다. 특히 다음 세 가지다.
  - 서버 측 fallback(`fallbacks: "default"`)
  - MCP connector
  - web search

## 알려진 제약과 다음 할 일
- **기록 수정 불가**: 메시지 수정이나 응답 재생성은 지원하지 않는다(append-only 기록). 필요하면 새 대화로 분기하는 방식으로 만든다.
- **bash 상태**: 환경변수와 백그라운드 프로세스는 명령 사이에 유지되지 않는다. 작업 디렉토리와 파일만 유지된다.
- **이번 범위에서 뺀 것**: 로컬(stdio) MCP 서버, 도구 실행 전 사람 승인, 사용자별 API 키, 사용량 한도
- **샌드박스 파일 보기**: UI에서 샌드박스 파일을 내려받거나 탐색하는 기능은 아직 없다.
